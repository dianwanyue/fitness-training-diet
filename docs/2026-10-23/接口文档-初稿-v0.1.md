## 1 概述

### 1.1 适用范围

本文档定义 FTDMS 手机端（Vue 3 + Capacitor）与服务端（Spring Boot）之间的 HTTP JSON 接口，覆盖认证与账户、目标、训练、饮食、身体数据、统计分析、AI 分析与后台管理 8 类共 **41 个接口**，并规定统一的传输、认证、响应、错误码与校验约定。

### 1.2 接口族总览

| 族 | 前缀 | 加工编号 | 接口数 | 说明 |
| --- | --- | --- | --- | --- |
| A 认证与账户 | `/auth`、`/users` | P1 | 6 | 注册、登录、注销、资料与密码 |
| A 目标 | `/goals` | P1 | 2 | 每日能量与营养目标 |
| B 训练 | `/exercises`、`/plans`、`/workouts` | P2 | 10 | 动作库、计划、打卡、训练记录 |
| C 饮食 | `/foods`、`/diet-records`、`/nutrition` | P3 | 6 | 食物检索、按餐次录入、当日汇总 |
| D 身体数据 | `/body-records` | P4 | 3 | 体重记录（同日唯一） |
| E 统计分析 | `/stats` | P5 | 3 | 训练完成率、摄入、体重趋势 |
| F AI 分析 | `/ai` | P6 | 7 | 授权、生成、历史报告 |
| G 后台管理 | `/admin` | P1–P3 | 4 | 动作库、食物库、账户状态（管理员） |

### 1.3 缩略语

API（应用程序接口）、JWT（JSON Web Token）、DTO（数据传输对象）、UPSERT（有则更新、无则插入）、ISO-8601（日期时间表示标准）。

## 2 通用约定

### 2.1 传输与编码

| 项 | 约定 |
| --- | --- |
| 协议 | HTTPS（开发期允许 HTTP://localhost） |
| 方法 | GET 查询、POST 新建、PUT 全量更新、PATCH 局部更新、DELETE 删除 |
| 媒体类型 | `application/json; charset=UTF-8` |
| 日期 | `yyyy-MM-dd`，例 `2026-10-23` |
| 时间 | `yyyy-MM-dd HH:mm:ss`，例 `2026-10-23 13:20:00` |
| 时区 | 业务时区统一 `Asia/Shanghai`，服务端按此时区归属每日记录 |
| 主键 | 19 位以内正整数（BIGINT），序列化为 JSON 数字 |
| 小数 | 数值字段最多 2 位小数，服务端先保留精度、展示层统一位数 |

### 2.2 认证与授权

- 登录成功后返回 JWT，客户端在后续请求的请求头携带：`Authorization: Bearer <token>`。
- 令牌有效期 **2 小时**，过期需重新登录（首版不提供刷新接口，作为范围守门的一部分）。
- 角色：`USER`（普通用户）、`ADMIN`（管理员）。
- **用户归属校验**：所有带 `user_id` 语义的资源，服务端一律以令牌解析出的用户身份为准，忽略请求中传入的 `userId`，防止越权访问。管理接口（`/admin/**`）单独鉴权，非 `ADMIN` 返回 `40302`。

### 2.3 统一响应结构

```json
{
  "code": 0,
  "message": "OK",
  "data": {},
  "timestamp": "2026-10-23 13:20:00",
  "traceId": "b7f1c2d3e4a5"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | int | 0 表示成功，非 0 为错误码（见 2.4） |
| message | string | 成功为 `OK`，失败为用户可读的中文提示 |
| data | object / array / null | 业务数据；失败时为 `null` |
| timestamp | string | 服务端响应时间（`yyyy-MM-dd HH:mm:ss`） |
| traceId | string | 12 位十六进制链路标识，便于排查 |

### 2.4 错误码

| 错误码 | HTTP | 含义 | 典型场景 |
| --- | --- | --- | --- |
| 0 | 200 | 成功 | — |
| 40001 | 400 | 参数缺失或格式错误 | 正则校验不通过 |
| 40002 | 400 | 参数取值超出范围 | 体重 350kg、克重 0 |
| 40101 | 401 | 未登录或令牌无效 | 缺少/伪造令牌 |
| 40102 | 401 | 令牌已过期 | 超过 2 小时 |
| 40301 | 403 | 无权访问该资源 | 访问他人训练记录 |
| 40302 | 403 | 需要管理员权限 | 普通用户调用 `/admin/**` |
| 40401 | 404 | 资源不存在 | 计划/记录/报告 id 不存在 |
| 40901 | 409 | 唯一性冲突 | 用户名已注册 |
| 40902 | 409 | 当前状态不允许该操作 | 已取消计划再次打卡 |
| 42901 | 429 | 请求过于频繁 | 登录连续失败 |
| 50001 | 500 | 服务端内部错误 | 未捕获异常 |
| 60001 | 200 | AI 模型不可用（降级） | 模型未启动，仅返回统计值 |
| 60002 | 200 | AI 分析超时（降级） | 超过 60 s |
| 60003 | 200 | 未授权 AI 分析 | 授权已撤回或未授权 |

> `6xxxx` 为**业务降级码**：HTTP 状态仍为 200，`data` 中保留原始统计摘要，前端提示"稍后重试"，不得展示为分析结论。

### 2.5 分页约定

请求：`page`（默认 1，≥1）、`size`（默认 20，1–100）；排序默认按业务时间倒序。

```json
{ "list": [], "total": 0, "page": 1, "size": 20 }
```

### 2.6 幂等与并发

| 场景 | 约定 |
| --- | --- |
| 同日体重 | `POST /body-records` 采用 UPSERT：同一用户同一 `recordDate` 重复提交视为更新，返回 200 与更新后实体 |
| 打卡 | 计划状态由 `PLANNED` → `COMPLETED` 单向流转，重复打卡返回 `40902` |
| 授权 | 同一用户仅保留一条有效授权，重复授权返回已有记录 |
| 并发更新 | 更新类接口以 `updatedAt` 作为乐观校验字段，不一致返回 `40902` |

### 2.7 数据校验总则

字段级正则与取值区间见《附录 C 数据字典》。总则：

1. 字符串先 `trim`，再按正则校验，不允许仅由空白字符组成；
2. 数值按十进制校验，不接受科学计数法与千分位分隔符；
3. 日期必须为合法日历日（如 `2026-02-30` 拒绝），`birthDate` 不得晚于当天；
4. `recordDate` / `plannedDate` 允许区间为 **[当天 − 365 天, 当天 + 7 天]**，超界返回 `40002`；
5. 枚举字段大小写敏感，仅接受表列取值；
6. 校验失败时 `message` 指明字段中文名与违反的规则，例："体重(kg) 需在 20–300 之间"。

## 3 接口明细

> 路径统一前缀 `/api/v1`。下表"权限"列中：匿名 = 无需令牌；本人 = 需令牌且仅限本人数据；管理 = 需 `ADMIN`。

### 3.1 认证与账户（P1）

#### A1 注册

`POST /api/v1/auth/register` · 权限：匿名

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| username | string | 是 | `^[A-Za-z0-9_]{4,20}$`，唯一 |
| password | string | 是 | 8–32 位，至少含字母与数字 |
| nickname | string | 否 | 1–50 字符，可中文 |
| gender | string | 否 | `MALE`/`FEMALE`/`UNKNOWN`，默认 `UNKNOWN` |
| birthDate | string | 否 | `yyyy-MM-dd`，≤ 当天 |
| heightCm | number | 否 | 100–250 |

```json
// 请求
{ "username": "fangwj", "password": "Fit2026abc", "nickname": "文锦", "gender": "MALE", "birthDate": "2003-05-12", "heightCm": 176.5 }
// 响应 data
{ "userId": 10001, "username": "fangwj", "role": "USER", "status": "ACTIVE" }
```

错误：`40001` 格式错误、`40002` 超范围、`40901` 用户名已存在。

#### A2 登录

`POST /api/v1/auth/login` · 权限：匿名

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| username | string | 是 | `^[A-Za-z0-9_]{4,20}$` |
| password | string | 是 | 8–32 位 |

```json
// 响应 data
{ "token": "eyJhbGciOiJIUzI1NiJ9...", "expiresIn": 7200, "role": "USER", "userId": 10001, "nickname": "文锦" }
```

错误：`40101` 用户名或密码错误、`40302` 账户已被禁用（`status=DISABLED`）、`42901` 连续失败 5 次后限流 60 s。

#### A3 注销

`POST /api/v1/auth/logout` · 权限：本人 · 响应 `data: null`（服务端将令牌加入失效集合）。

#### A4 查询本人资料

`GET /api/v1/users/me` · 权限：本人

```json
// 响应 data
{ "userId": 10001, "username": "fangwj", "nickname": "文锦", "gender": "MALE",
  "birthDate": "2003-05-12", "heightCm": 176.50, "status": "ACTIVE",
  "createdAt": "2026-10-23 13:20:00", "updatedAt": "2026-10-23 13:20:00" }
```

#### A5 修改本人资料

`PUT /api/v1/users/me` · 权限：本人 · 请求体字段同 A1（不含 `username`、`password`）；`username` 与 `role` 不可修改。

#### A6 修改密码

`PUT /api/v1/users/me/password` · 权限：本人

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| oldPassword | string | 是 | 与当前密码匹配 |
| newPassword | string | 是 | 8–32 位，至少含字母与数字，且 ≠ oldPassword |

### 3.2 每日目标（P1）

#### A7 查询当前生效目标

`GET /api/v1/goals/current?date=2026-10-23` · 权限：本人

返回 `effectiveDate ≤ date` 的最近一条；不存在时 `data: null`（前端显示"暂未设置"，**不补零**）。

```json
{ "goalId": 5001, "effectiveDate": "2026-10-20", "kcal": 2200.00,
  "proteinG": 140.00, "carbG": 250.00, "fatG": 60.00 }
```

#### A8 设置目标

`POST /api/v1/goals` · 权限：本人 · 同一天已有目标则覆盖（`uk_goal_user_date`）

| 字段 | 类型 | 必填 | 区间 |
| --- | --- | --- | --- |
| effectiveDate | string | 是 | `yyyy-MM-dd`，允许区间同 2.7 第 4 条 |
| kcal | number | 是 | 500–6000 |
| proteinG | number | 否 | 0–1000，默认 0 |
| carbG | number | 否 | 0–1000，默认 0 |
| fatG | number | 否 | 0–1000，默认 0 |

### 3.3 训练（P2）

#### B1 检索动作库

`GET /api/v1/exercises?keyword=深蹲&muscleGroup=腿部&page=1&size=20` · 权限：本人

返回公共动作（`isPublic=1`）与本人自定义动作（`createdBy=当前用户`），排除 `status=DISABLED`。

```json
{ "list": [{ "exerciseId": 301, "name": "杠铃深蹲", "muscleGroup": "腿部",
             "equipment": "杠铃", "isPublic": true }], "total": 1, "page": 1, "size": 20 }
```

#### B2 新建训练计划（含动作）

`POST /api/v1/plans` · 权限：本人 · 事务内写入 `training_plan` + `plan_item`

```json
// 请求
{ "plannedDate": "2026-10-24", "title": "胸+三头", "note": "注意肩部热身",
  "items": [
    { "exerciseId": 301, "targetSets": 4, "targetReps": 8, "targetWeightKg": 60.00 },
    { "exerciseId": 305, "targetSets": 3, "targetReps": 12 }
  ] }
// 响应 data
{ "planId": 9001, "status": "PLANNED", "plannedDate": "2026-10-24", "itemCount": 2 }
```

校验：`items` 长度 1–20；`targetSets` 1–20；`targetReps` 1–100；`targetWeightKg` 0–500（可空，自重动作留空）。

#### B3 按区间查询计划

`GET /api/v1/plans?start=2026-10-20&end=2026-10-26&status=PLANNED` · 权限：本人

返回要素：`planId`、`plannedDate`、`title`、`status`、`itemCount`、`completedItemCount`。

#### B4 查询计划详情

`GET /api/v1/plans/{planId}` · 权限：本人 · 含 `items[]` 与已关联的 `workoutLogId`（可为 `null`）。

#### B5 修改计划

`PUT /api/v1/plans/{planId}` · 权限：本人 · 仅 `status=PLANNED` 可改；**已存在训练记录时不得覆盖记录**，仅更新计划本身。

#### B6 计划打卡

`POST /api/v1/plans/{planId}/complete` · 权限：本人

```json
// 请求：可选，用于同时落训练记录
{ "performedAt": "2026-10-24 19:30:00",
  "sets": [{ "exerciseId": 301, "setNo": 1, "weightKg": 60.00, "reps": 8, "completed": true }] }
```

状态流转 `PLANNED → COMPLETED`；计划不存在 `40401`；已取消/已完成 `40902`。

#### B7 取消计划

`POST /api/v1/plans/{planId}/cancel` · 权限：本人 · `PLANNED → CANCELLED`；已完成的计划不允许取消（`40902`）。

#### B8 新建训练记录（可关联计划，支持临时训练）

`POST /api/v1/workouts` · 权限：本人 · 事务内写 `workout_log` + `workout_set`

```json
{ "planId": null, "performedAt": "2026-10-23 20:10:00", "note": "临时加练",
  "sets": [{ "exerciseId": 310, "setNo": 1, "weightKg": 40.00, "reps": 15, "completed": true }] }
```

`planId` 为 `null` 表示临时训练；`sets` 长度 1–50。

#### B9 按区间查询训练记录

`GET /api/v1/workouts?start=2026-10-01&end=2026-10-23&page=1&size=20` · 权限：本人

返回 `workoutLogId`、`planId`、`performedAt`、`logDate`、`setCount`、`totalVolumeKg`（Σ 重量×次数，仅统计 `completed=1`）。

#### B10 删除训练记录

`DELETE /api/v1/workouts/{workoutLogId}` · 权限：本人 · 级联删除其 `workout_set`；关联计划状态不回退（由前端提示）。

### 3.4 饮食（P3）

#### C1 检索食物库

`GET /api/v1/foods?keyword=鸡胸&state=COOKED&page=1&size=20` · 权限：本人

返回每 100 g 营养值与来源，供前端预览换算结果。

```json
{ "list": [{ "foodId": 701, "name": "鸡胸肉", "brand": null, "kcalPer100g": 133.00,
             "proteinPer100g": 24.60, "carbPer100g": 2.50, "fatPer100g": 2.60,
             "state": "COOKED", "source": "《中国食物成分表》第6版" }],
  "total": 1, "page": 1, "size": 20 }
```

#### C2 新增饮食记录

`POST /api/v1/diet-records` · 权限：本人

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| recordDate | string | 是 | `yyyy-MM-dd`，区间同 2.7 第 4 条 |
| meal | string | 是 | `BREAKFAST`/`LUNCH`/`DINNER`/`SNACK` |
| foodId | number | 是 | 存在且 `status=ACTIVE` |
| grams | number | 是 | 1–2000 |

服务端按 `每100g值 × grams ÷ 100` 计算并落 4 个 `snapshot_*` 字段与 `snapshot_source`。

```json
// 响应 data
{ "dietRecordId": 8801, "recordDate": "2026-10-23", "meal": "LUNCH",
  "foodId": 701, "grams": 150.00,
  "snapshotKcal": 199.50, "snapshotProteinG": 36.90, "snapshotCarbG": 3.75, "snapshotFatG": 3.90 }
```

#### C3 按日期查询饮食记录

`GET /api/v1/diet-records?date=2026-10-23` · 权限：本人 · 按 `meal` 分组返回。

#### C4 修改饮食记录

`PUT /api/v1/diet-records/{dietRecordId}` · 权限：本人 · 修改 `grams` 后**重新计算并覆盖快照**。

#### C5 删除饮食记录

`DELETE /api/v1/diet-records/{dietRecordId}` · 权限：本人

#### C6 当日营养汇总

`GET /api/v1/nutrition/daily?date=2026-10-23` · 权限：本人

```json
{ "date": "2026-10-23", "recordCount": 5,
  "intake": { "kcal": 1850.00, "proteinG": 132.40, "carbG": 198.10, "fatG": 52.30 },
  "goal": { "kcal": 2200.00, "proteinG": 140.00, "carbG": 250.00, "fatG": 60.00 },
  "diff": { "kcal": -350.00, "proteinG": -7.60, "carbG": -51.90, "fatG": -7.70 },
  "recorded": true }
```

`recorded=false` 表示当日无任何记录，此时 `intake` 各值为 0 且 `goal` 可能为 `null`，前端须显示"未记录"而非"摄入 0"。

### 3.5 身体数据（P4）

#### D1 记录体重（同日 UPSERT）

`POST /api/v1/body-records` · 权限：本人

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| recordDate | string | 是 | `yyyy-MM-dd`，区间同 2.7 第 4 条 |
| weightKg | number | 是 | 20–300 |
| note | string | 否 | ≤500 字符 |

#### D2 按区间查询体重

`GET /api/v1/body-records?start=2026-09-24&end=2026-10-23` · 权限：本人

返回 `list[]`（`recordDate` 升序）与 `validDays`（有效记录天数）。缺失日期**不出现在列表中**，由前端断线绘制。

#### D3 删除体重记录

`DELETE /api/v1/body-records/{bodyRecordId}` · 权限：本人

### 3.6 统计分析（P5）

#### E1 训练完成率

`GET /api/v1/stats/training?start=2026-10-17&end=2026-10-23` · 权限：本人

```json
{ "start": "2026-10-17", "end": "2026-10-23",
  "planTotal": 5, "planCompleted": 3, "planCancelled": 1,
  "planCompletionRate": 0.75,
  "extraWorkoutCount": 2,
  "daily": [{ "date": "2026-10-17", "plannedCount": 1, "completedCount": 1, "extraCount": 0 }],
  "emptyPlan": false }
```

口径：`planCompletionRate = planCompleted ÷ (planTotal − planCancelled)`；`planTotal − planCancelled = 0` 时 `emptyPlan=true` 且 `planCompletionRate=null`（显示"暂无计划"）；临时训练单独计入 `extraWorkoutCount` 与 `extraCount`。

#### E2 区间营养摄入

`GET /api/v1/stats/nutrition?start=2026-10-17&end=2026-10-23` · 权限：本人

返回每日 `intake` 与 `goal`、`validDays`、`avgKcal`（仅按有效日计算）、`missingDates[]`。

#### E3 体重趋势

`GET /api/v1/stats/weight?start=2026-09-24&end=2026-10-23` · 权限：本人

```json
{ "validDays": 18, "first": { "date": "2026-09-24", "weightKg": 74.20 },
  "last": { "date": "2026-10-23", "weightKg": 72.60 }, "deltaKg": -1.60,
  "avg7d": 73.05, "avg7dValidDays": 6, "series": [] }
```

`avg7d` 按最近 7 个自然日内的有效记录求均值，并同时返回 `avg7dValidDays`；`validDays=0` 时 `avg7d=null`。

### 3.7 AI 分析（P6）

#### F1 查询授权状态

`GET /api/v1/ai/consent` · 权限：本人

```json
{ "granted": true, "scope": "BODY_DIET_TRAINING_30D", "grantedAt": "2026-10-20 09:12:00", "revokedAt": null }
```

#### F2 授权 AI 分析

`POST /api/v1/ai/consent` · 权限：本人

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| scope | string | 是 | 固定 `BODY_DIET_TRAINING_30D`（首版唯一取值） |

写入 `ai_consent`（`status=GRANTED`）；已存在有效授权时返回原记录（幂等）。

#### F3 撤回授权

`DELETE /api/v1/ai/consent` · 权限：本人 · 置 `status=REVOKED`、`revokedAt=now`；撤回后 F4 返回 `60003`。

#### F4 生成分析报告

`POST /api/v1/ai/reports` · 权限：本人 · 同步接口，前端超时设 60 s

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| period | number | 否 | `7` 或 `30`，默认 30 |

```json
// 响应 data（成功）
{ "reportId": 1201, "periodStart": "2026-09-24", "periodEnd": "2026-10-23",
  "validDays": 26, "status": "SUCCESS", "modelName": "Qwen3-4B-Instruct-2507",
  "createdAt": "2026-10-23 13:30:12",
  "content": "【数据概况】…\n【训练执行】…\n【营养摄入】…\n【体重趋势】…【可采取的调整】…" }
```

降级：模型不可用返回 `code=60001`；超 60 s 返回 `60002`；此时 `data` 为 `{"reportId":1201,"status":"DEGRADED","digest":{…}}`，仅含统计摘要。未授权返回 `60003`。

#### F5 查询历史报告

`GET /api/v1/ai/reports?page=1&size=20` · 权限：本人 · 返回 `reportId`、`periodStart`、`periodEnd`、`status`、`createdAt`、`contentPreview`（前 100 字）。

#### F6 查看报告详情

`GET /api/v1/ai/reports/{reportId}` · 权限：本人 · 返回 `content` 与 `digest`（解析后的 `summary_json`）。

#### F7 删除报告

`DELETE /api/v1/ai/reports/{reportId}` · 权限：本人 · 物理删除，不可恢复。

## 4 关键数据结构

### 4.1 AI 分析输入摘要 `summary_json`

由服务端在调用模型前生成并入库（`ai_report.summary_json`），同时用于**数值核对**：模型正文中出现的数值须与摘要一致，不一致不展示为确定结论。

```json
{
  "period": { "start": "2026-09-24", "end": "2026-10-23", "days": 30, "validDays": 26 },
  "profile": { "gender": "MALE", "age": 23, "heightCm": 176.5, "weightKg": 72.6 },
  "training": { "planTotal": 12, "planCompleted": 8, "planCancelled": 1,
                "completionRate": 0.727, "extraWorkoutCount": 3,
                "byMuscleGroup": [{ "muscleGroup": "腿部", "setCount": 42 }] },
  "nutrition": { "avgKcal": 2080.5, "avgProteinG": 128.2, "avgCarbG": 232.0, "avgFatG": 58.4,
                 "goalKcal": 2200, "validDays": 24,
                 "missingDates": ["2026-10-05", "2026-10-11"] },
  "weight": { "first": 74.2, "last": 72.6, "deltaKg": -1.6, "avg7d": 73.05, "validDays": 18 },
  "notes": ["2026-10-11 无饮食记录", "力量训练集中在腿部"]
}
```

约束：`missingDates` 最多 30 项；`notes` 最多 10 条、每条 ≤50 字符；整体序列化后 ≤ 8 KB（受 CPU 推理能力约束，见 FAR 风险 R1）。
