## 实现内容

| 接口 | 能力 | 关键规则 |
| --- | --- | --- |
| G1 `GET /ai/consent` | 查询授权 | 从未授权返回 `granted=false` 与默认范围 |
| G2 `POST /ai/consent` | 授予授权 | 首版仅 `BODY_DIET_TRAINING_30D`；已有有效授权幂等 |
| G3 `DELETE /ai/consent` | 撤回授权 | 无有效授权返回 5001；历史报告保留 |
| G4 `POST /ai/reports` | 生成报告 | `periodDays` 缺省 30；未授权 5001；有效记录 <3 天 5003；模型失败降级 DEGRADED |
| G5 `GET /ai/reports` | 历史分页 | 仅本人；生成时间/主键倒序；含 `periodDays`、`validDays` |
| G6 `GET /ai/reports/{id}` | 报告详情 | 返回 `summaryJson`（DS15）与 `notice` |
| G7 `DELETE /ai/reports/{id}` | 删除报告 | 物理删除；越权统一 1004 |

实现要点：

- **先算后解释**：摘要复用 F1–F3 统计口径，训练/营养/体重数值全部由后端计算；模型只接收摘要。
- **有效天数**：饮食记录日 ∪ 训练记录日 ∪ 体重记录日，缺失日不补零、不参与均值。
- **摘要上限**：序列化 ≤8 KB，超限抛实现异常并降级，不写入超长 JSON。
- **模型调用**：Ollama `/api/chat`，连接超时 3 s、读取超时 60 s；不可达/非 2xx/空正文均转 DEGRADED。
- **输出核对**：检查五段标题与关键数值；不一致时不改写正文，在 `notice` 中提示“以统计值为准”。
- **隐私**：摘要只含性别、年龄、身高、体重与统计值，不含姓名、手机号、用户名。
- **错误码**：摄入克重越界由 1001 改为 4001，与接口文档 2.8 一致。
- **字段级校验**：1001 响应补 `data.errors:[{field,message}]`，与接口文档 2.6 一致；业务错误仍保持 `data:null`。
